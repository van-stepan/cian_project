# Handoff — выгрузка поставок и приёмок ВБ по складам Удмуртии

Документ для продолжения работы на другом устройстве / в другой сессии
(desktop / web / CLI). Читается самостоятельно — контекст не потеряется.

- **Репозиторий:** `van-stepan/cian_project`
- **Ветка:** `claude/wb-deliveries-ur-export-rtdj6g`
- **Папка с работой:** `wb_export/`
- **Дата:** 2026-07-24

---

## Зачем это делалось

Нужно документально подтвердить (по запросу госорганов), что у пользователя
были поставки / товарооборот, связанные с **Удмуртской Республикой**.
Склады Wildberries в Удмуртии — **«Ижевск»** и **«Сарапул»**.

Требовалось выгрузить из ЛК маркетплейса:
1. поставки с датами и списком артикулов на склады ВБ в Удмуртии;
2. акты о приёмке товара на этих складах.

## Важный контекст про репозиторий

Репозиторий `cian_project` **не имеет отношения к Wildberries** — это старый
парсер объявлений ЦИАН (недвижимость, Python 2, выгрузка в PostgreSQL). Поэтому
никаких данных ВБ здесь изначально не было и быть не могло. Работа по ВБ
вынесена в **отдельную папку `wb_export/`**, чтобы не смешивать с чужим кодом.

## Что сделано

Создан самостоятельный Python 3 скрипт, который ходит в **официальное API
Wildberries под API-ключом пользователя** и выгружает его собственные данные.
Ничего не генерируется и не выдумывается: что вернёт API — то и попадёт в файл.

Файлы в `wb_export/`:

| Файл                      | Назначение                                  |
|---------------------------|---------------------------------------------|
| `wb_udmurtia_export.py`   | основной скрипт выгрузки                     |
| `README.md`               | инструкция по запуску                        |
| `requirements.txt`        | зависимости (`requests`, `openpyxl`)         |
| `HANDOFF.md`              | этот файл                                    |

### Что именно выгружает скрипт

1. **Поставки (поступления на склад)** — эндпоинт
   `GET /api/v1/supplier/incomes` (статистический API,
   `https://statistics-api.wildberries.ru`, категория ключа «Статистика»).
   Поля: дата поступления, дата приёмки (`dateClose`), склад, артикул продавца,
   баркод, `nmId`, количество, сумма, `incomeId`. Отбираются только строки, где
   склад содержит «ижевск» / «удмурт» (регистронезависимо, по вхождению).
   - Лист **«Поставки (сводка)»** — одна строка на поставку (`incomeId`) со
     списком всех артикулов и суммарным количеством.
   - Лист **«Поставки (детально)»** — построчно.

2. **Приёмка (платная приёмка)** — эндпоинт
   `GET /api/v1/analytics/acceptance-report` (аналитический API,
   `https://seller-analytics-api.wildberries.ru`, категория ключа «Аналитика»).
   Период режется на окна ≤ 31 дня (ограничение API). Записи привязываются к
   поставкам в Удмуртию по `incomeId` из отобранных поступлений, есть дедуп на
   границах окон.
   - Лист **«Приёмка (акты)»**.

3. **Документы-акты о приёмке (PDF/ZIP)** — по флагу `--download-acts`, через
   API документов (`https://documents-api.wildberries.ru`, категория ключа
   **«Документы»**): `GET /api/v1/documents/list` (постранично, `limit≤50`) +
   `GET /api/v1/documents/download` (контент в base64) — плюс служебный
   `GET /api/v1/documents/categories`. Файлы декодируются из base64 и
   сохраняются в `<out>_acts/`, перечень — на лист **«Документы (акты)»**.
   Служебные режимы: `--list-doc-categories`, `--list-docs`.
   **Важно:** документы НЕ фильтруются по складу — акты берутся за период и
   сопоставляются к Удмуртии по дате/`incomeId` через лист «Поставки».

Результат: `udmurtia_wb_export.xlsx` (3–4 листа) + CSV в кодировке UTF-8 с BOM
(корректно открываются в Excel); с `--download-acts` — ещё папка
`<out>_acts/` со скачанными PDF/ZIP и `<out>_akty_dokumenty.csv`.

## Как запустить

```bash
pip install -r wb_export/requirements.txt

# Токен: ЛК продавца -> Настройки -> Доступ к API
# (нужны категории «Статистика», «Аналитика», для актов — «Документы»)
export WB_API_TOKEN="ваш_токен"

python3 wb_export/wb_udmurtia_export.py --date-from 2023-01-01 --date-to 2024-12-31
# + скачать акты-документы (PDF/ZIP):
python3 wb_export/wb_udmurtia_export.py --date-from 2023-01-01 --download-acts
```

Параметры: `--date-from` (обяз.), `--date-to` (по умолч. сегодня),
`--warehouse СЛОВО` (можно несколько; по умолч. Ижевск/Сарапул/Удмурт),
`--out ПРЕФИКС`, `--no-acceptance`, `--download-acts`, `--doc-category`,
`--acts-keyword`, `--list-doc-categories`, `--list-docs`, `--doc-locale`.

Для тестов без боевого API есть переопределение базовых адресов через окружение:
`WB_STATISTICS_BASE`, `WB_ANALYTICS_BASE`, `WB_DOCUMENTS_BASE`.

## Что проверено

- компиляция (`py_compile`), валидация аргументов (нет токена / перевёрнутый период);
- агрегация артикулов по `incomeId` (`build_summary`);
- фильтр складов, включая Ижевск и Сарапул (`matches_warehouse`);
- разбивка периода на окна ≤ 31 дня без пропусков и нахлёстов + дедуп приёмки;
- документы: список с пагинацией, отбор актов по ключевым словам, скачивание и
  **декодирование base64** в PDF, манифест;
- запись CSV и Excel (3–4 листа: жирные заголовки, закрепление строки, автоширина).

Всё прогонялось **end-to-end против локального мок-сервера** WB (через
`WB_*_BASE`) — HTTP-поток, пагинация, фильтры и base64 подтверждены. Реальный
API в этой среде заблокирован сетевой политикой, ключа пользователя тут нет —
данные подтянутся при запуске на ноутбуке с настоящим `WB_API_TOKEN`.

## Нюансы / ограничения

- **Лимиты запросов.** У API ВБ строгие лимиты (статистика — нередко ≤ 1 запроса
  в минуту; документы — пачками по 5 за 10 c). Скрипт сам делает паузы и повторы
  на `429`/`5xx`.
- **Документы не фильтруются по складу.** Акты приёмки выдаются по всему
  кабинету; к Удмуртии сопоставляются по дате/`incomeId` через лист «Поставки».
  Отбор среди документов — по ключевым словам (`приёмк`/`приемк`/`acceptance`)
  или по точной категории (`--doc-category`; посмотреть список —
  `--list-doc-categories`).
- Если поступлений по складам Удмуртии за период нет — скрипт честно сообщает и
  оставляет листы пустыми.
